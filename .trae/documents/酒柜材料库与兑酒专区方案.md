# 酒柜材料库 + 兑酒专区 + 星级评价 实施方案

## Context（背景与目标）

「融酒」是纯静态本地网页调酒 App（双击 `index.html` 即用，数据存浏览器 localStorage）。用户这次提出 3 个新功能 + 3 个修改：

**新功能**
1. **我的材料 → 能做什么酒**：录入自己手头有的配料/辅料，按这些材料筛出「现在就能做」的酒。必须持久化。
2. **做过的酒 + 星级**：给酒打 1~5 星，必须持久化（关掉再打开还在）；推荐页刷到时显示「已喝过」标签。
3. **兑酒专区**：中国饮料（雪碧/可乐/冰红茶/王老吉/椰树/养乐多/酸梅汤…）兑酒这类喝法单独建一个区域。

**修改**
4. **去掉所有「适量」**：改成「根据个人口味」，不许再出现「适量」。
5. **材料筛选太少**：胶囊从 24 个加到 60 个（保留现有搜索框作为自定义入口，不再另加输入框）。
6. （随 3 一起）新增的兑酒配方要有地方展示。

**现状事实（已实测）**
- 现有「中国饮料兑酒」配方极少：雪碧 36 / 可乐 32 / 姜汁汽水 48 / 柠檬水 47 / 茶饮 40 / 汤力水 24 / 椰汁 6 / 红牛 4 / 养乐多 2 / 芬达 1 / 王老吉·酸梅汤 0，且散落在西方配方里；`category` 字段有 200+ 种杂乱取值，**无法靠分类划分专区** → 需要新写配方。
- `ingredients_zh` 里含「适量」**1348 行**、含「按个人口味」16 行，全部由 `tools/normalize-units.js` 产出（4 处）。
- 材料筛选来自 `tags.commonIngredients(list, 24)`；`tags.ingredientName()` / `ingredientNames()` 会自动去掉括号里的用量，可直接复用。
- `tools/gen-data.js:15` 硬编码 `drinks.length !== 1395` 熔断；测试里 6 处硬编码 1395/1394。

## 一、兑酒专区（新功能 3）

### 1.1 数据：新写 36 条配方，id 前缀 `cn-`
- 新增 `tools/seed-mixer.js`：内含 36 条配方数据 + 合并逻辑，**幂等**（按 `id` 去重，重复执行不会重复插入）。
- 合并进 `素材/index.zh.json` 的 `drinks` 数组，`total` 同步改为 1431，`with_image` 不变（新配方无图，卡片显示占位图标 🍸）。
- 配方内容：中国常见瓶装饮料 + 各种基酒，每条约 2~4 行配料，用量沿用现有规范格式（如 `伏特加（45 毫升）`、`雪碧（加至满杯）`）。
  - 覆盖：雪碧、可乐、冰红茶、茉莉绿茶、元气森林式气泡水、王老吉、椰树椰汁、养乐多、酸梅汤、美年达、汤力水、干姜水、AD钙奶、冰红茶/奶茶 等 × 伏特加/朗姆/威士忌/金酒/龙舌兰/白酒/清酒/啤酒。
  - 字段齐全：`id / name / name_zh / name_display（必须「中文（English）」格式）/ category（统一填「饮料兑酒」）/ alcoholic / glass / ingredients_zh / instructions_zh`；`ingredients_en` / `instructions_en` 留空字符串。
- `tools/gen-data.js:15` 的数量守卫改为 `drinks.length >= 1395`（不再卡死具体数字，改完仍能挡住"文件被清空"这类事故）。

### 1.2 新增第 4 个 tab「兑酒」
- `js/core.js`：`PAGES` 加 `'mixer'`（`parseHash`/`buildHash` 用白名单判断，自动生效，无需其他改动）。
- `index.html`：`.tabbar` 加 `<a href="#/mixer" data-tab="mixer" class="tab"><span class="tab-ico">🥤</span><span>兑酒</span></a>`。
- `js/app.js`：`PAGE_TITLE` 加 `mixer: '兑酒'`；`render()` 加 `else if (page === 'mixer') renderMixer();`。
- `js/ui.js`：新增 `mixerHtml({list}, tagsApi)` —— 顶部一句说明（N 条 · 点卡片看做法）+ 逐条 `cardHtml(d, {}, tagsApi)`。**必须逐条渲染**，不能用 `cardListHtml`（它只接受一个 opts）。
- `js/app.js` 的 `renderMixer()`：从 `store.allRecipes()` 取 `id` 以 `cn-` 开头的配方（它们已在主库，所以点卡片进详情、加入酒柜都天然可用）。

**沿用不动的（已确认无需改）**：`.tabbar/.tab` 的 CSS（`flex:1` 自动适配 4 个）；`onHashChange` 的幂等跳过；`resetRecommendList()`（`else if (r.page !== 'drink')` 已兜住 `mixer`）；滚动恢复逻辑（推荐页↔详情仍恢复，切到 mixer 再回推荐页则重置）；tabs 高亮（循环按 `querySelectorAll('.tab').length` 驱动）。

## 二、我的材料 → 能做的酒（新功能 1）

### 2.1 持久化：新键 `rj.pantry`（`js/store.js`）
- `KEYS` 加 `pantry: 'rj.pantry'`；新增 `getPantry` / `addPantry` / `removePantry` / `togglePantry`（照抄 `getCabinet` 那几个的写法）。
- `getPantry` 读取时清洗：非数组 → `[]`；过滤非字符串；`trim()`；去重。
- `addPantry` 空串抛错、重复返回 `false`。
- **`clearAll()` 遍历 `Object.keys(KEYS)`，加了 KEYS 就自动清，无需改动。**

### 2.2 匹配逻辑：放 `js/tags.js`（不放 core）
理由：需要私有的 `ingredientNames()` 与 `ING_STOP`（`ING_STOP` 现在没导出）。core 的定位是路由/筛选编排，配料语义归 tags；且 tags 本身就是纯函数可单测。

```js
/* 双向包含：pantry「朗姆酒」能命中配方「白朗姆酒」，反向也命中 */
function ingMatches(a, b) {
  return !!a && !!b && (a === b || a.indexOf(b) !== -1 || b.indexOf(a) !== -1);
}

/* 返回「还缺的材料名」：[] = 齐全，[x] = 还差 1 样，null = 无可统计材料（全是冰/水），不参与 */
function pantryMissing(drink, pantry) { ... }   // 跳过 ING_STOP 的冰/水，不算缺

/* 汇总两组 */
function pantryGroups(list, pantry) {
  return { ready: [{drink, missing:null}...], near: [{drink, missing:'青柠汁'}...] };
}
```
- 边界：`od-hot-water` / `od-ice-cold-water` 这类只有白名单材料的配方返回 `null`，不进任何一组。
- 性能：实测 1395 条 × pantry 20 项 ≈ 3.6 ms，无需缓存/索引/debounce。
- **不动 `hasIngredient`**（推荐页筛选仍是单向包含语义）。

### 2.3 酒柜页改造（`renderCabinet()`）
现在只有「空状态 / 卡片列表」两分支，改成四块（顺序：我的材料 → 能做的酒 → 我的酒柜 → 喝过的酒），HTML 全部交给 `ui.js` 的 `cabinetHtml(...)` 拼接，`renderCabinet()` 只负责取数。

`ui.js` 拆成几个纯函数：`pantryPanelHtml(pantry, draft)`、`makeableHtml(ready, near, tagsApi)`、`cabinetListHtml(items, tagsApi)`、`ratedSectionHtml(rated, tagsApi)`（第三块见 §3）。
- 我的材料为空 → 隐藏「能做的酒」整块，只留输入引导。
- 我的酒柜的空状态文案「酒柜还空着…」**保持不变**（有测试依赖）。
- 喝过的酒为空 → 整块隐藏。
- 「材料齐全 / 还差 1 样」两组各截断到 20 条并显示「共 N 款」（pantry=20 时齐全 113 条、差 1 样 352 条，不做分页）。

### 2.4 输入交互（关键：打字时不能重渲染）
复用 `bindEvents()` 里 document 级 `input` 委托，**打字阶段只更新 `state.pantryDraft`，不重渲染**；回车/点＋时才提交并重渲染，重渲染后照 `bindSearch()` 的手法恢复焦点。
- `state` 新增 `pantryDraft: ''`。
- document 级 `input` 委托加：`if (t.getAttribute('data-pantry-input') !== null) { state.pantryDraft = t.value; return; }`
- 新增 document 级 `keydown` 委托处理 Enter（`e.key === 'Enter' || e.keyCode === 13`）。
- 提交时用 `tags.ingredientName(raw)` 归一（用户输「30毫升朗姆酒」→「朗姆酒」），入库 → 清 `pantryDraft` → `renderCabinet()` → 恢复输入框焦点。
- `pantryPanelHtml` 把 `state.pantryDraft` 写回 `value="..."`，保证重渲染不丢输入。
- `handleAction` 新增 `addPantry` / `delPantry`（data-val = 材料名）。

## 三、做过的酒 + 星级评价（新功能 2）

### 3.1 持久化：新键 `rj.ratings`（对象 `{id: 1..5}`）
- `cleanRating(n)`：只接受 `1..5` 的**整数**（`Number()` 归一，`"3"` 收为 3；`0/6/401/-1/2.5/"abc"/null` 丢弃）。
- `getRatings()`：非对象/数组 → `{}`；逐条用 `cleanRating` 清洗。
- `getRating(id)`；`setRating(id, n)`：`0` 或 `'0'` = 取消（删键），非法值抛错（与 `addCabinet` 抛「非法 id」风格一致）。
- **`SCHEMA` 保持 1，不 bump**（可选新增字段，新旧备份双向兼容）。

### 3.2 渲染
- `ui.js` 新增 `rateStarsHtml(id, rating)`：5 个 `★`（`data-act="rate"` `data-id` `data-val="1..5"`，当前星级高亮），后面跟「已喝过 ★N / 未评价」。详情页、酒柜「喝过的酒」列表共用。
- `cardHtml` 的 opts 增加两个可选字段（**只增不改，向后兼容**）：
  - `opts.rating`（单条）或 `opts.ratings`（`{id:星级}` 映射，供 `cardListHtml` 单 opts 场景用）→ 有分时加 `<span class="chip accent">已喝过 ★N</span>`。
  - `opts.missing` → 加 `<span class="chip">还差 X</span>`（「能做的酒」用）。
- `detailHtml` opts 加 `rating`，在按钮行后插一块 `<div class="detail-section"><h3>我的评价</h3>…</div>`。
- 新 `ratedSectionHtml(rated, tagsApi)`：标题「喝过的酒（N）」+ 按星级**降序**（同级按名称）列出，每条带星级控件（可改星/取消）。
- `app.js`：`renderDetail` 传 `rating: store.getRating(d.id)`；`recommendParts` 的 opts 里并入 `ratings: store.getRatings()`（推荐卡片也显示「已喝过」）。
- `handleAction` 新增 `case 'rate'`：`cur === rv ? setRating(id, 0) : setRating(id, rv)`，然后 `render()`。点星星时 `closest('[data-act]')` 会命中星星本身，不会误触发卡片的 `open`。

### 3.3 备份三处同步
- `exportBackup()` 追加 `pantry` / `ratings`。
- `parseBackup()` **不加必填校验**（保持只有 `cabinet`/`custom` 必填，否则旧备份被拒、`phase3` 现有用例语义变化）。
- `importBackup()`：`replace` 分支写入这两个键（写盘后由 `getPantry/getRatings` 再清洗）；`merge` 分支 pantry 取并集去重、ratings 浅合并（导入值优先）。
- `clearAll()` 无需改动。

## 四、去掉「适量」（修改 4）

`tools/normalize-units.js`：
1. 把所有产出 `'适量'` 的地方（4 处：`convertMeasure` 里"数量+英文形容词"与"纯英文说明"两个分支、`normalizeLine` 里"英文括号说明"与"无用量补适量"两个分支）统一改成 `'根据个人口味'`。
2. `TEXT_MEASURES` 里原有的 `'按个人口味'` 标签也统一成 `'根据个人口味'`（全库一个说法）。
3. `NORMALIZED_RE` 与 `LOOKS_MEASURE` 的关键词同步换成新词。
4. 在 `normalizeLine` 开头加一条**迁移规则**：若末尾括号以「适量」或「按个人口味」开头，就地改成「根据个人口味」并**保留后面的 `；备注`**（如 `打发奶油（适量；冰镇）` → `打发奶油（根据个人口味；冰镇）`）。这样重跑脚本就能修掉已有的 1348+16 行，且幂等。
5. 重跑 `node tools/normalize-units.js` → `node tools/gen-data.js`，断言数据里「适量」计数为 0。

## 七、验收

**自动测试**：`node --test "tests/*.test.js"` 全绿（当前 96 → 预计 110+）。
覆盖的关键不变式：
- `Core.parseHash('#/mixer').page === 'mixer'`；mixer 页渲染出 36 张卡片、tab 高亮；

- `pantryGroups`：`ready` 全是齐全、`near` 全差 1 样；
- 录入材料：打字阶段 `state.pantryDraft` 更新但 `view().innerHTML` 不变（不丢焦点）；提交后入库并出现胶囊；删除可移除；
- `setRating`：`0` 取消、`6`/`401`/`'abc'` 抛错；`getRatings` 丢弃脏值、非对象返回 `{}`；详情页点第 4 星 → 4 星，再点同一星 → 取消；卡片出现「已喝过 ★4」；
- 「喝过的酒」按星级降序；备份导出/导入（replace + merge）能还原 pantry 与 ratings；
- 数据层：「适量」在 `index.zh.json` 与 `data.js` 里计数为 **0**。

**浏览器实机验收**（临时起本地静态服务，验证完删除临时文件）：

## 八、风险与取舍

1. **新配方进入全局库**：36 条兑酒会同时出现在推荐页与盲盒里（不只是兑酒 tab）。这带来更多选择，但会稀释现有库。若你希望只在兑酒 tab 出现，需要额外在 `filteredList()` 与 `blindPool` 里排除 `cn-`（一行的事，但会改变推荐页内容，需你确认）。**默认保留在全局。**
2. **兑酒配方用我的常识撰写**，不联网抓取；无图片（显示占位图标）。用量按现有规范写「材料名（用量）」，口味标签/价格由现有规则自动推导。
3. **「根据个人口味」替代「适量」**：像「冰块（根据个人口味）」读起来略别扭，但这是你明确的要求；我会统一全库用词，不再出现「适量」。
4. **材料筛选胶囊从 24 增到 60**：筛选条首屏会被材料分组占更多竖向空间（材料分组本身是横向滚动的一行，高度不变），需要实机看一眼观感。
5. **材料匹配是「名字包含」而非「真库存」**：录入「朗姆酒」会认为你有了「白朗姆酒 / 黑朗姆酒」；不涉及数量与替代关系（如"没有青柠汁，用柠檬汁代替"），这是有意的简化。
