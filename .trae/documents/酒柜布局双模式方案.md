# 酒柜界面双布局方案（经典 / 抖音「我」范式）

## Context

当前酒柜页（`#/cabinet`）是**单列纵向堆叠**：我的材料 → 能做的酒 → 我的酒柜 → 喝过的酒 → 浏览历史入口。
用户认为这套结构不符合预期，希望：

- **重新设计酒柜界面的整体布局**，参考抖音 App「我」页面的范式：**上下分区** —— 顶部固定展示核心信息区、中部为可滑动的内容列表、底部保留必要的功能操作入口；
- 新增一个**固定夹层按钮**（位于标题栏与底部导航之间的独立夹层，不归任何页面所有），**一键切换**到新布局；
- **两种布局自由切换**，切换过程流畅无卡顿；
- 只做界面结构调整，**数据与业务逻辑不变**。

已确认的两个关键决策（用户选择）：

1. 切换按钮形态：**固定夹层按钮**（独立于页面内容的一层，全局可见）
2. 新布局中部组织方式：**统计卡 + 3 Tab** —— 顶部统计卡（酒柜 N / 喝过 N / 材料 N / 浏览 N）+「我的材料」入口按钮；中部用「酒柜 / 喝过 / 能做」三个 Tab 切换列表；底部保留浏览历史入口

**默认仍是现有经典布局**（store 缺省值 `classic`），保证既有 217 项测试与现有用户习惯不受影响，新布局是可选升级。

---

## 1. 状态与持久化

### `js/store.js`

复用已有的 `getSettings()/setSettings()`（`api.getSettings` 已存在，`rj.settings` 键已在用），只加两个薄封装：

```js
api.getCabinetLayout = function () {
  // 只认 'profile'，其余（含脏值）一律回落 classic
  return api.getSettings().cabinetLayout === 'profile' ? 'profile' : 'classic';
};
api.setCabinetLayout = function (v) {
  return api.setSettings({ cabinetLayout: v === 'profile' ? 'profile' : 'classic' }).cabinetLayout;
};
```

放 `rj.settings` 而不是新开键，好处：导出备份自动带上（`exportBackup` 已含 `settings`），换机还原后布局偏好跟着走。

### `js/app.js`

`state` 增加两个字段：

- `cabinetLayout`: 初值 `null`，`start()` 里从 `store.getCabinetLayout()` 读取
- `cabinetTab`: `'cabinet'`（默认）/ `'rated'` / `'makeable'`

## 2. 固定夹层按钮

### `index.html`

在 `.topbar` 与 `.view` 之间插入一层（flex 列的兄弟节点，永远可见、不随内容滚动）：

```html
<div class="switchbar">
  <button id="btnLayout" class="layout-btn" title="切换酒柜布局" aria-label="切换酒柜布局">
    <span class="lb-ico">⇄</span><span class="lb-txt">酒柜布局：经典</span>
  </button>
</div>
```

### `js/app.js`

- `bindEvents()` 里按现有 `btnSettings` 的写法绑 `btnLayout` 的 click → `handleAction('toggleCabinetLayout', null)`
  （`tests/fakedom.js` 的 `getElementById` 会自动建桩，绑定安全）
- 新增 `syncLayoutBtn()`：写 `#btnLayout` 的文案（经典 / 新版）与 `.on` 类名；在 `start()` 与每次布局切换后调用
- 新增 `case 'toggleCabinetLayout'`：翻转 store 值 → 同步 `state.cabinetLayout` → `syncLayoutBtn()` → 若当前在 `#/cabinet` 则重绘该页 → `toast('已切换到' + '经典/新版' + '酒柜布局')`

夹层在所有页面可见（用户选择的「全局」语义）；该按钮只影响酒柜页，其他页面点了会静默改状态并给出 toast 提示。

## 3. 新布局渲染

### `js/ui.js` 新增 `cabinetProfileHtml(opts, tagsApi)`

结构（上下分区）：

| 区域 | 内容 | 复用 |
| --- | --- | --- |
| **顶部固定信息区** `.profile-head` | 圆牌头像（🍸）+「我的酒柜」+ 副标题；4 格统计行 `.profile-stats`（酒柜 / 喝过 / 材料 / 浏览）；「我的材料」入口按钮 `data-act="openPantry"` | 统计数字来自 `opts` |
| **Tab 栏** `.profile-tabs` | 3 个 Tab：酒柜 / 喝过 / 能做，带数量角标 `data-act="cabTab" data-val="cabinet\|rated\|makeable"` | — |
| **中部内容列表** | 按 `opts.tab` 三选一 | **直接复用 `cabinetListHtml` / `ratedSectionHtml` / `makeableHtml`** |
| **底部功能入口** | 浏览历史入口 | **复用 `historyEntryHtml`** |

关键点：Tab 主体**不重写**，直接调用现有三个 builder。这样「能做的酒」顶部那条规则说明（`rulenote`，属于硬性约束）、「我的酒柜（N 瓶）」「喝过的酒（N）」等文案原样保留，数据获取逻辑也完全共用一份。

`opts` 由 `renderCabinet()` 组装，把现有 `cabinetHtml` 的参数原样传入，**额外加** `tab`、`layout`、`historyCount`。

### `js/app.js` 改 `renderCabinet()`

数据组装部分**不动**（`ids/cabinet/pantry/groups/ratings/rated/history` 那一段保持原样），只在最后按布局分派：

```js
var payload = { pantry, pantryDraft, pantrySuggest, ready, near, cabinet, rated, history, historyCount, tab: state.cabinetTab };
view().innerHTML = (state.cabinetLayout === 'profile')
  ? ui.cabinetProfileHtml(payload, tags)
  : ui.cabinetHtml(payload, tags);
```

### 新增动作分支 `case 'cabTab'`

`state.cabinetTab = data-val` → 只重绘中部列表。为「切换流畅无卡顿」，不整页重渲染，而是定点替换 `#cabList` 的 innerHTML（Tab 高亮用 class 切换）。

## 4. 「我的材料」在 profile 下改为底部弹层

经典布局里它是页面内嵌面板，profile 布局下改为入口按钮 + 复用同一个面板：

- `js/app.js` `renderOverlay()` 加分支：

  ```js
  else if (kind === 'pantry') ov.innerHTML = ui.pantryPanelHtml(store.getPantry(), state.pantryDraft, pantrySuggestNames());
  ```

- 新增 `case 'openPantry': openOverlay('pantry'); break;`
- **重绘目标要分情况**：`addPantry` / `delPantry` / `addPantryName` 现在收尾调用 `renderCabinet()`（`js/app.js` 约 988、994 行）。改为走一个 `refreshAfterPantry()`：overlay 为 `pantry` 时重绘弹层，当前页是 cabinet 时同时重绘页面。否则 profile 模式下点「＋」会看不到反馈。
- `js/app.js` 约 1404 行的 `#pantrySuggest` 输入联动是定点更新，弹层内同样生效，不用改。

## 5. CSS（`css/style.css`）

沿用现有夜空 + 水晶变量，不引入新配色。

- `.switchbar`：夹层容器，`background: rgba(9,12,28,.66)` + `backdrop-filter: blur(12px)` + 下边框 `var(--line)`，右下角对齐，高约 40px
- `.layout-btn`：**蓝色水晶**（`--ice-grad` / `--ice-inset` / `--ice-line`）胶囊，`hover` 提亮、`active` 缩放，与 `.exact-toggle` 同一套材质语言
- `.profile-head`：`position: sticky; top: 0; z-index: 3`，毛玻璃底；`margin: -14px -14px 0` 抵消 `.view` 的 `padding: 14px`，让固定头贴边；内部自己补 `padding`
- `.profile-stats`：4 等分 grid，数字用 **金色水晶**渐变文字（`--gold-grad` + `background-clip: text`），标签用 `--muted`
- `.profile-tabs`：横向 3 Tab，未选 `--ink-soft`，选中金色高亮 + 底部一道金色发光短线；`.on` 复用 `.ftab.on` 的语言
- `.profile-tab-count`：金色水晶小角标，与 `.ftab i` 一致
- 响应式：`.phone` 的 `max-width: 420px` 与 `>=460px` 圆角边框分支不动，统计行与 Tab 都用 flex/grid 自适应，窄到 320px 不出横向溢出

> ⚠️ 设计约束（来自既有记忆）：`.filter-panel` 那种「按主题变量分层」的写法要避免在新结构里漏变量导致浅底残留 —— 新类一律直接引用现有水晶/夜空变量，并在实现后用脚本核对「无未定义变量、无未使用变量」。

## 6. 测试（新增 `tests/phase17.test.js`）

1. `store.getCabinetLayout()` 默认 `classic`；`setCabinetLayout('profile')` 持久化；非法值回落 `classic`
2. `handleAction('toggleCabinetLayout')` 切换状态并写盘；**重建 app 后仍是 profile**（持久化）
3. `#btnLayout` 文案随模式变化（经典 / 新版）
4. `UI.cabinetProfileHtml(...)` 渲染出：统计行四个数字、三个 Tab（`data-act="cabTab"`）、`data-act="openPantry"` 入口
5. profile 布局下 `go(app,'#/cabinet')` 能渲染酒柜列表（`我的酒柜（1 瓶）`）与「喝过的酒」的 `data-act="rate"` 星星
6. `cabTab` 切到 `rated` / `makeable` 后中部内容随之变化
7. 点 `openPantry` 后 `state.overlay === 'pantry'`；弹层内「＋」加材料后弹层内容同步更新
8. **回归**：默认 classic 布局下 `UI.cabinetHtml` 的关键文案与现有断言完全一致（`能做的酒` / `我的材料` / `我的酒柜（N 瓶）` / `喝过的酒（N）` / rulenote）
9. 夹层按钮存在且不与底部导航 tab 冲突（`querySelectorAll('.tab')` 仍为 3）
