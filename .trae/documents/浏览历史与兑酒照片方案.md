# 浏览历史 + 兑酒专区真实照片 实施方案

## Context（背景与目标）

「融酒」是纯静态本地网页调酒 App（`file://` 双击即用、不联网、数据存 localStorage）。上一轮刚加了「兑酒」tab（36 条 `cn-` 配方）。用户这次提两件事：

1. **浏览历史**：记录打开过哪款酒，显示「xx年xx月xx日xx点xx分」这种时间（类似闲鱼的足迹），能自己删单条记录。
2. **兑酒配方补真实照片**：36 款新配方目前只有占位图标，要结合配料表配上真实照片。用户希望优先找**国内来源（小红书 / 抖音）**。

**已实测的现状**
- 联网可用：直连 `thecocktaildb.com` 正常（HTTP 200，图片能下载），系统代理当前关闭（`ProxyEnable=0`）。
- 现有素材同源：`素材/thecocktaildb/images/<id>-<Name>.jpg`（627 张）、`素材/opendrinks/images/`；抖音那 11 条用的是散图 `素材/dy-grx-XX.jpg`。
- `tools/gen-data.js` 会把 `image` 字段自动加 `素材/` 前缀，所以库内只要写 `cn/cn-001-xxx.jpg`。
- **小红书 / 抖音的搜索页在静态抓取（WebFetch）下拿不到结果**（返回的只有「综合/视频/用户/直播」导航壳），需要真实浏览器渲染，且多数要登录；图片在受保护 CDN 上。上一轮抓抖音成品帧的成功做法是：浏览器打开视频页 → `video.currentTime` + `seeked` → `canvas.drawImage` 提帧 → 截图裁剪（不下载视频）。

## 一、浏览历史（明确、低风险）

### 1.1 持久化：新键 `rj.history`（`js/store.js`）
数组、**最新在前**，每项 `{ id, at }`（`at` = 毫秒时间戳），最多保留 **100** 条：

- `getHistory()`：非数组 → `[]`；逐项校验（`id` 为字符串且非空、`at` 为有限数字），按 id 去重（保留最新那条）。
- `pushHistory(id, at)`：已存在则先删掉旧记录再插到最前（同时刷新时间）；超出 100 条裁掉尾部。
- `removeHistory(id)` / `clearHistory()`。
- **`clearAll()` 遍历 KEYS，自动覆盖，无需改动**；`exportBackup` / `importBackup` 同步带上（`replace` 全量替换、`merge` 按 id 取较新的那条），`parseBackup` 保持不加必填校验（旧备份仍可导入）。

### 1.2 时间格式化：放 `js/core.js`（纯逻辑、可单测）
`core.formatStamp(ms)` → `2026年10月08日 21点30分`
（月份 / 日期 / 时 / 分补零，按用户说的「xx年xx月xx日xx点xx分」格式；非法入参返回空串。）

### 1.3 记录时机（`js/app.js`）
`handleAction('open')` 里，在跳详情前记一条 `store.pushHistory(id, now())`。
- 为了可测，加时钟注入：`var now = typeof deps.now === 'function' ? deps.now : Date.now;`（与现有 `deps.seed` / `deps.random` 风格一致）。
- 只在打开详情时记（切 tab、筛选项不算浏览）。

### 1.4 展示：酒柜页新增第 5 块「浏览历史」（`js/ui.js` + `js/app.js`）
放在现有的「我的材料 → 能做的酒 → 我的酒柜 → 喝过的酒」之后：

- 标题 `浏览历史（N）`，右上角一个「清空」（`data-act="clearHistory"`，二次确认）。
- 每行：小卡片（紧凑模式，不显示「加入酒柜」按钮）+ 一行灰色时间 `2026年10月08日 21点30分` + 右侧 ✕ 删除（`data-act="delHistory" data-val="<id>"`）。
  - 点行本身仍走 `data-act="open"` 进详情；✕ 在卡片内层，`closest('[data-act]')` 命中 ✕，不会误触发打开。
- 页面最多列最近 **20** 条，超出显示「仅显示最近 20 条，共 N 条」；为空则整块不显示（避免酒柜页过长）。
- 找不到对应配方（配方被删）的历史项自动跳过。

## 二、兑酒专区真实照片（分阶段、带兜底）

### 2.1 存储与命名
- 新增子目录 `素材/cn/`，文件命名 `cn-001-Sprite-Vodka.jpg`（跟随现有 `<id>-<Name>.jpg` 风格）。
- `素材/index.zh.json` 里给 36 条 `cn-` 配方补 `image: 'cn/cn-001-Sprite-Vodka.jpg'`；`gen-data.js` 会自动加 `素材/` 前缀。

### 2.2 取图策略（按你的要求优先国内来源）
**第一步：真实浏览器去抖音 / 小红书抓（先做 6 款样本）**
- 用浏览器打开抖音/小红书，按酒名（雪碧伏特加、冰红茶威士忌、王老吉威士忌…）搜索，挑一条**画面干净、能看出这杯酒**的笔记/视频，用上一轮验证过的办法取图：视频走 `canvas` 提成品帧，图文笔记直接取图。
- 遇到登录墙 → 暂停，请你扫码登录一次后继续。
- 抓 6 款后**先给你看效果**（截图对照），你认可再继续把剩下 30 款做完。

**第二步（兜底）：找不到 / 质量差的用同源真实照片补齐**
- 优先在 TheCocktailDB 里找**同名或同配方**的真实调酒照片（如 自由古巴 Cuba Libre、金汤力 Gin and Tonic、朗姆可乐、雪碧伏特加 Vodka with Sprite 等都有）；
- 再退一步用「配料最接近」的那款照片；
- **保证 36 款都有一张真实照片**，不会留占位图标。
- 若某款确实只能兜底，会在 PRO.md 里注明哪些是兜底图，方便你后续替换。

**下载方式**：写一个脚本 `tools/fetch-mixer-images.js`，内置「id → 图源 URL」映射表，逐张下载到 `素材/cn/` 并校验（HTTP 200、文件体积 > 5KB、扩展名合法）；**幂等**（已存在且体积>0 就跳过，可加 `--force` 重下）。国内来源如果只能靠浏览器截图得到，就先把截图落到 `素材/cn/`，同名的直接从映射表里省掉。

### 2.3 入库与验证
1. 图片落盘到 `素材/cn/`。
2. `tools/seed-mixer.js` 里给 36 条配方补 `image` 字段（幂等，重跑会更新同 id 记录）。
3. `node tools/gen-data.js` 重新生成 `js/data.js`（它会打印缺图数量，必须为 0）。
4. 浏览器抽查：兑酒页 36 张卡片都有图、点进详情大图正常。

## 四、验收

**自动测试**：`node --test "tests/*.test.js"` 全绿（当前 113 → 预计 125+）。
覆盖：`formatStamp` 格式与补零/非法入参；同一款重复打开只留一条且时间刷新；超过 100 条裁剪；`removeHistory`/`clearHistory`；重新创建 app 后历史仍在；备份导出导入（replace + merge）还原；酒柜页出现「浏览历史」块与时间文案；36 条 `cn-` 配方 `image` 字段非空且文件真实存在（`fs.existsSync`）。

**浏览器实机**（临时起本地静态服务，验完删除临时文件）：
1. 点开几款酒的详情 → 酒柜页「浏览历史」按时间倒序出现，显示「2026年10月08日 21点30分」；
2. 删单条 ✕ 生效；「清空」二次确认后清空；
3. 关掉浏览器重开，历史还在（localStorage 持久化）；
4. 兑酒页 36 张卡片全部有真实照片，点进详情大图正常；
5. 推荐页/盲盒里这些兑酒卡片也显示照片。

## 五、风险与取舍

1. **小红书 / 抖音不一定抓得动**：搜索页需 JS 且常要登录，图片在受保护 CDN 上。所以采用「先试抓 6 款样本 → 给你确认 → 再批量」的方式，避免闷头做完 36 款才发现风格不对或全被挡住。**如果你不接受兜底图（只用国内来源），可能出现部分款没图**——我建议保留兜底，保证每款都有真图。
2. **兜底图是「同款或最接近」的真实调酒照片**，不一定 100% 就是这一款；会在 PRO.md 里标注哪些是兜底，方便你后续替换成自己拍的。
3. **图片版权**：仅本地个人自用（与现有 627 张素材同性质）；下载源在 PRO.md 里记录，便于你日后核对。
4. **浏览历史上限 100 条**：闲鱼式的足迹会无限增长，本地存储需要收敛；100 条足够回看，超出自动丢最旧的。
5. **酒柜页会变长**：已经 4 块，再加历史变 5 块；历史块默认只列 20 条且为空时不显示，尽量不干扰前面内容。
